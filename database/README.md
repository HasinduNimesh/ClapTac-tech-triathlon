# Database

Waypoint uses **one PostgreSQL instance** in Milestone 1.

Logical schema ownership:

| Schema | Owner service |
|---|---|
| `orders` | order-service |
| `planning` | planning-service |
| `fleet` | fleet-service |
| `loading` | loading-service |
| `delivery` | delivery-service |
| `shared` | shared-service (also the product catalog) |
| `audit` | shared-service |
| `inventory` | inventory-service (planned; tables only for now) |
| `ai` | insights-service (planned; tables only for now) |

Services must not query another schema. Example: delivery-service must not `SELECT` from `orders.orders`; it calls Order Service over HTTP.

`0001_init.sql` creates extensions and schemas only. Domain tables arrive with Milestone 2+.

Do not create a database per service yet.

## Catalog, store stock and agent data (migrations 0050–0053)

| Migration | Tables |
|---|---|
| `0050_shared_product_catalog.sql` | `shared.product_categories`, `products`, `product_fresh`, `product_style`, `product_tech`, `product_aliases`, `product_prices`, `outlet_products` |
| `0051_orders_order_lines.sql` | `orders.order_lines`, `orders.receipt_lines` |
| `0052_inventory_schema.sql` | `inventory.simulation_runs`, `stock_levels`, `stock_batches`, `stock_movements` (append-only ledger), `sales`, `sale_lines`, `stock_counts` |
| `0053_ai_schema.sql` | `ai.agents`, `observations` (raw, append-only), `insights`, `suggestions`, `suggestion_responses`, `agent_preferences`, `agent_runs` |

They are numbered from 0050 so they apply after the 0040–0045 migrations in open pull requests. They were tested together with every migration from those PRs.

- **Units.** A *pack* (crate, case, bag, carton) is what moves through ordering, loading and delivery, and matches `orders.order_units`. An *each* is one sellable item in a store. `shared.products.units_per_pack` converts between them; `inventory.*` counts eaches.
- **Cross-schema links** (for example `inventory.stock_levels.product_id` or `ai.suggestions.user_id`) are plain IDs, not foreign keys.
- **A3/A4 data** (habit patterns, automations) lives in `shared.*` from PR #34 and is not duplicated in `ai`.
- **Agents** never connect to PostgreSQL; they reach `ai` through insights-service.

### Seed data

- `seeds/catalog.sql`, generated by `scripts/generate-catalog-seed.py`: 24 categories, 114 products across Fresh, Style and Tech (in-store GTIN-13 barcodes, effective-dated LKR prices, everyday aliases), and 5,093 store-range rows. Store size, and so range width and daily sales targets, comes from each outlet's weekly order units in the official `deliveries_train.csv`.
- `seeds/inventory_history.sql`: eight weeks of trading for every store product, ending yesterday. It covers scheduled deliveries rounded to whole packs, first-expiry-first-out sales, expiry and breakage write-offs, and Sunday stock counts. It then builds weekly `ai.observations` and `ai.insights` (waste risk, stock-out risk and sales trends) from that ledger. Every row is `simulated = true` under the `seed-baseline` simulation run. It runs once (about two minutes); delete that run to regenerate. OUT034 includes the demo case: 20 of 48 bottles of Fresh milk 1 L expired last week.
